# 输出格式规范

> 本 skill 定位为**发现型/浏览型**，输出以简洁摘要为主，不需要学术或工程报告级别的严密引用。

---

## 1. 通用输出结构

```
## 概览
（1-3 句话，今天/本周值得关注的事情）

## 值得关注
- **标题**：要点描述
- **标题**：要点描述
...

## 来源
- [信源名] 标题 — URL — YYYY-MM-DD
```

---

## 2. 信源标注（简化版）

发现型输出只需标注最关键的几个字段：

| 字段 | 说明 |
|------|------|
| `[信源名]` | 消息源简称 |
| 标题 | 原文标题或内容概述 |
| URL | 完整链接 |
| 日期 | `YYYY-MM-DD`，未知标 `时间不详` |

信源等级只在必要时标注，不强制每条都标：

| 标签 | 使用场景 |
|------|----------|
| `[一手]` | 官方 Blog/通讯社原发，需要强调权威性时 |
| `[存疑]` | 单源、社交媒体线索，提醒读者谨慎 |

---

## 3. 时效标记

| 标记 | 含义 |
|------|------|
| 🕐 | 本周/本月新动态 |
| 📚 | 趋势/背景，不强调时效 |
| ⚠️ | 超过 6 个月，可能已过时 |

---

## 4. 领域特定要求

### LLM 领域
- 论文动态一句话 TL;DR，附 arXiv 编号即可，不展开方法/实验。
- 多个模型动态聚合时用简洁列表，不需对比表格。

### AI Agent 领域
- 框架更新一句话说明"更新了什么"，附官方博文链接。
- 发现热门新项目时，给 GitHub star 数 + 一句话卖点。

### 前端开发领域
- 浏览器新特性一句话 + 最低支持版本。
- 框架更新标注是否包含 breaking change。

### 国际局势领域
- 强制展示交叉验证：至少 2 个信源。
- 争议话题标注各方立场。
