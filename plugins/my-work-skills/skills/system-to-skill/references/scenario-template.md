# 场景清单格式（01-scenarios.md）

读者：负责审核的人（了解业务但不看代码）。**不出现源码路径/类名/技术栈。**

## 文件头

```
# <系统名> 场景清单
- 面向角色：
- 场景总数：N（读 x / 写 y）
- 推荐纳入：… / 推荐排除：…
```

## 单个场景格式

```
### S01 查询订单物流进度
- 类型：读 | 写（风险：低/中/高）
- 目标角色：业务员、跟单员
- 用户会怎么说：
  - "PO2026-0815 那批货到哪了？"
  - "帮我看下我最近发出去的柜子有没有延误"
- 输入信息：订单号 / 运单号 / 柜号（用户不给时如何引导）
- 处理逻辑（业务语言）：先按单号定位订单 → 取运单列表 → 取最新物流节点
- 关键输出：当前节点、预计到港日、是否延误、最新事件
- 前置条件与权限：仅项目组成员可见；…
- 状态与限制：…
- 已知例外/坑：一个订单多运单时需让用户选择
- 不确定点：→ 见 02-open-questions Q3
- 建议：纳入 | 排除（理由）
```

## 排除项清单

单独列出被排除的功能类别与理由（如：字典维护、报表导出），让审核者知道"没漏，是有意不做"。

## 开发者信息去向

每个场景对应的接口、代码位置、涉及的表，写入 `dev-notes.md`，按场景编号（S01…）索引。
